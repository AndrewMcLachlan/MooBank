# CLAUDE.md — MooBank Web App

This file provides guidance for AI agents working on the MooBank React frontend. It is the single source of frontend conventions.

## Technology Stack

- **React 19** with TypeScript
- **Vite 7** - Build tool
- **TanStack Router** - File-based client-side routing (`src/routes/`, generated `src/routeTree.gen.ts` via `@tanstack/router-plugin`)
- **TanStack Query v5** - Server state management
- **React Hook Form** - Form handling
- **Redux Toolkit** - LEGACY: transaction-list UI state only. Do not add new slices; new UI state goes in router search params or local state.
- **Chart.js / react-chartjs-2** - Data visualisation
- **date-fns** - Date manipulation
- **@andrewmclachlan/moo-ds** - Custom design system components (Storybook: https://storybook.mclachlan.family)
- **@andrewmclachlan/moo-app** - Application framework (bootstrapper, layout, MSAL auth)
- **@andrewmclachlan/moo-icons** - Custom icon library

TypeScript settings: `strictNullChecks: false` and `noImplicitAny: false` are **accepted trade-offs** for TanStack Router's typed params — do not "fix" them.

### TypeScript packages — read before changing them

The project compiles with **TypeScript 7 and must stay on it**. The dependency layout looks wrong at a glance, but is deliberate:

| package.json entry | Provides | Consumed by |
|---|---|---|
| `"@typescript/native": "npm:typescript@^7.0.2"` | the **TS 7** compiler → the `tsc` binary | `build`, `typecheck`, `trace` |
| `"typescript": "npm:@typescript/typescript6@^6.0.2"` | the **TS 6.0 compiler API** (plus a `tsc6` binary) | ESLint only |

TypeScript 7.0 ships **no programmatic API** — `require("typescript")` returns only `{ version, versionMajorMinor }`, and the API is due in 7.1. Type-aware linting needs `ts.TypeFlags`/`ts.createProgram`, so typescript-eslint cannot run against TS 7. This is **not** a peer-range problem and `overrides` cannot force it; the npm-alias arrangement is [Microsoft's recommended workaround](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

- **Never "fix" lint by downgrading the compiler.** `tsc` is TS 7. The `typescript` alias is lint tooling, not the compiler.
- Check `npx tsc --version` (must be 7.x) after any dependency change — the compat package pulls real TS 6 in as `@typescript/old`, which also carries a `tsc` binary and could win the bin if `@typescript/native` is removed.
- **Remove this when** typescript-eslint supports the TS 7.1 API: drop `@typescript/native`, set `"typescript": "^7.x"`, restore `tsc`.

## Project Structure

```
src/
├── api/                # GENERATED by @hey-api/openapi-ts — never hand-edit
│   ├── types.gen.ts    # Source of truth for API shapes
│   ├── sdk.gen.ts      # Typed API functions
│   └── @tanstack/react-query.gen.ts  # Generated query options / mutations / keys
├── routes/             # TanStack Router file-based routes
│   └── <feature>/      # Route files + co-located private dirs:
│       ├── -components/   # Feature-private components ("-" prefix = ignored by router)
│       ├── -hooks/        # Feature-private data hooks
│       └── -utils/        # Feature-private helpers
├── components/         # Cross-feature shared components
├── hooks/              # Cross-feature shared hooks
├── models/             # Small supplemental types only (types.gen.ts is the API source of truth)
├── store/              # LEGACY Redux (transaction lists only)
├── utils/              # Shared utilities (dates, currency, query persistence)
├── css/                # Feature stylesheets, imported into App.css
└── routeTree.gen.ts    # GENERATED route tree — never hand-edit
```

Placement rule: a hook/component used by one feature lives in that route's `-hooks/`/`-components/`; used across features → `src/hooks/`/`src/components/`. Exception: `routes/-dashboard/` is a privileged aggregator and may import other features' private dirs.

## Adding a New Feature

1. Build the backend, then `npm run generate` to regenerate API types (the OpenAPI spec regenerates on `dotnet build` — no need to run the API).
2. Create route files in `src/routes/<feature>/` using `createFileRoute`. The Vite plugin regenerates `routeTree.gen.ts` automatically.
3. Co-locate data hooks in `-hooks/`, consuming the generated options from `api/@tanstack/react-query.gen`.
4. Add navigation entries where required and feature CSS under `src/css/` (see CSS Conventions).

## Data Layer Patterns

All API access goes through the generated client — there are no hand-coded HTTP services.

### Queries

Use the generated options directly:

```typescript
import { useQuery } from "@tanstack/react-query";
import { getTagsOptions } from "api/@tanstack/react-query.gen";

const { data: tags } = useQuery(getTagsOptions());
```

### Mutations — the canonical idiom

Generated mutation + `onSettled` invalidation with generated query keys, wrapped in `toast.promise` for user feedback (see `routes/groups/-hooks/useCreateGroup.ts`):

```typescript
export const useCreateThing = () => {
    const queryClient = useQueryClient();
    return useMutation({
        ...createThingMutation(),
        onSettled: () => queryClient.invalidateQueries({ queryKey: getThingsQueryKey() }),
    });
};
// caller: toast.promise(mutateAsync(...), { loading: ..., success: ..., error: ... })
```

Every user-visible mutation gets `toast.promise`. Use `setQueryData` only for deliberate optimistic updates, and always with rollback on error.

### Transaction lists — partial-key idiom

Transaction queries use centralised partial-key matching in `routes/accounts/-hooks/transactionKeys.ts` (`[{ _id: "getTransactions" }]`) with optimistic update + rollback. Follow that file; don't invent new key shapes.

### Paged endpoints

Generated options drop response headers, so paged queries pair the generated `*QueryKey` with a custom `queryFn` over `sdk.gen` to read `X-Total-Count` into `PagedResult<T>` (see `routes/accounts/-hooks/useTransactions.ts`).

## Forms

Use React Hook Form. When seed data arrives asynchronously (editing an entity loaded by query), use the `values:` option — never `defaultValues` + `useEffect`/`setValue`:

```typescript
const form = useForm<Thing>({ values: thing, resetOptions: { keepDirtyValues: true } });
```

See `routes/settings/institutions/-components/InstitutionForm.tsx`. Validation goes through RHF, not `window.alert`.

## State Management Philosophy

- **TanStack Query** - All server/API data
- **Router search params** - Shareable UI state (filters, pagination, sort)
- **useState** - Component-local state
- **Custom hooks with localStorage** - Persisted preferences
- **Redux** - Legacy transaction-list state only; being retired

## PWA & Query Persistence

- The service worker is registered via `vite-plugin-pwa` (`registerType: "autoUpdate"`). **Never remove the registration** — the PWA install depends on it.
- Query persistence uses an IndexedDB persister with a strict allowlist in `src/utils/queryPersister.ts`. Additions must be reference-data-like (tags, instrument lists, importer types). **Never persist transactions.**
- Post-login prefetch lives in `routes/__root.tsx` and must use the same generated options the consuming components use, so keys match.

## CSS Conventions

### Critical Rules

This app does **not** use Bootstrap (or any utility-CSS framework) — MooDS ships its own components and styles. Do not reach for atomic/utility class names; they are not defined and do nothing. **NEVER use utility CSS classes** such as:
- `d-flex`, `d-block`, `d-none`, etc.
- `justify-content-*`, `align-items-*`, `flex-*`
- `m-*`, `mb-*`, `mt-*`, `mx-*`, `my-*` (margin utilities)
- `p-*`, `pb-*`, `pt-*`, `px-*`, `py-*` (padding utilities)
- `text-center`, `text-muted`, `text-*`
- `w-*`, `h-*` (width/height utilities)
- `row`, `col`, `col-*` (grid utilities outside of proper layouts)

**Instead, use proper CSS with reusable classes:**
- Create semantic class names that describe the purpose (e.g., `filter-row`, `chart-container`, `tab-header`)
- Define layout using CSS Grid or Flexbox in stylesheet files
- Place styles in feature-specific CSS files under `src/css/`
- Import CSS files in `App.css` using `@import "css/featurename" layer(moobank);`

### General Guidelines

- Use CSS layers: `@layer mooapp, layout, moobank;` — feature styles go in `layer(moobank)`
- Column width classes: `column-15`, `column-20`, `column-25`, `column-50`
- Action columns: `row-action`
- Negative values: `negative` class; amount formatting: `amount` class
- Use nested CSS for component-scoped styles
- Prefer CSS Grid for layouts

## Component Usage (moo-ds)

- Use `Section` with a header instead of a Card
- Use `SectionTable` for tables with headers, `SectionForm` for forms within sections
- Inline-editable cells: `EditColumn`; row actions: `DeleteIcon`/`SaveIcon` in `<td className="row-action">`
- Icons from `@andrewmclachlan/moo-icons`: `Dashboard`, `PiggyBank`, `TwoCoins`, `Budget`, `Stack`, `Tags`, `Cog`, `Sliders`, `Reports`, `Rules`, `Transaction`, `Import`, `Trendline`, `BarChart`, `PieChart`, `Hierarchy`, and more

## Dates, Numbers & Charts

- **Dates**: date-fns only, via the helpers in `src/utils/dateFns.ts` — no `toLocaleDateString`, no other date libraries.
- **Currency/amounts**: use the `Amount` component (`src/components/Amount.tsx`) or the utilities in `src/utils/currency.ts` — don't hand-roll `Intl.NumberFormat`/`toFixed` in components.
- **Charts**: Chart.js via react-chartjs-2 (`ChartJS.register(...registerables)`).
